# Stable DIKW main-board bootstrap

## REST contract

Enabled by WorkspaceModule, the authenticated endpoint is:

POST /api/workspaces/:workspaceId/dikw/main-board

There is no request body. The normal server.path prefix (AFFINE_SERVER_SUB_PATH,
default empty) applies, exactly as it does to WorkspacesController. Successful
responses are HTTP 200 with Cache-Control: no-store:

    { version: 1, docId: string, rootUpdate: string, contentUpdate: string }

Both strings are base64 Yjs **V1** updates. rootUpdate is a complete root state
including the pre-existing meta.pages Y.Array parent and its dependencies; it is
not a stand-alone delta or a seed reusable across workspaces. Apply the returned
bytes to that workspace root and to the content Y.Doc with the returned docId.
Do not use ordinary DocsStore.createDoc(docId): it appends another metadata entry.
Do not create a replacement root/pages when the endpoint returns 409.

## Durability and permissions

- Global AuthGuard is retained. Every call requires Workspace.Read,
  Workspace.CreateDoc, root Doc.Read/Doc.Update, and main Doc.Read/Doc.Update.
  The existing-record path does not bypass those checks. This is intentionally
  not a read-only lookup endpoint.
- A ReadCommitted transaction locks the existing workspaces row FOR UPDATE,
  then reads/creates WorkspaceMainBoard with workspaceId as its primary key.
  Only the winner generates random docId and CRDT structs. Existing records are
  immutable through this service; no main-board reset/delete/rename-ID API exists.
- The only existing Y.Doc read is the root, via the native storage adapter's
  non-compacting getDocBinNative. No existing content document is read.
- Missing/malformed/incomplete meta.pages causes 409, with no bundle claim.
  Existing pages and graph entries are preserved. Only one page metadata record
  and board:docId in top-level dikw:board-graph:v1 are added.
- Content is generated by native createDocWithMarkdown('主白板', '', docId), the
  same writer used by DocWriter, without user body content.
- An existing board:* relation with parentId:null causes 409 before claim;
  local-to-cloud import must not silently acquire a second main board.
- Commit completes before content/root pushDocUpdates (content first). Each successful push uses
  the native doc.updates.pushed event protocol. The two documents are **not
  atomic together**. A failed request is retried with exactly the persisted bytes;
  it never generates another seed or docId. A zero timestamp is treated as a
  failed/dropped update, not successful bootstrap.
- Repeated pushes can append duplicate update rows; Yjs application is idempotent.
  Replaying original structs does not overwrite later user edits or undo CRDT
  deletions. Main-board deletion protection belongs to the client; this service
  never replaces its identity after deletion.

## Dependencies and verification

No package dependency changes. Uses existing Nest, Prisma, nanoid, Yjs and
@affine/server-native (affine_doc_loader 0.1.7 behind createDocWithMarkdown).
The added migration creates workspace_main_boards; Prisma client regeneration
and migration application are required before using the endpoint.
There is intentionally no document FK that could remove the claim on doc delete.
Workspace deletion cascades as normal.

The three __tests__/main-board*.spec.ts files contain 15 targeted AVA tests:
root-parent preservation, complete dependency closure, repeat/concurrent merges,
409 and duplicate seed rejection; persisted bytes across retries/recreated service
instances, first root/content push failure, dropped updates, pre-push commit,
auth/permissions; and controller method/path/status/subject wiring. The service
harness emulates transactions in memory; it is NOT a PostgreSQL concurrency test.
The native content test checks page/surface/title/linkage and later-edit replay.

These tests have been written but NOT run in this change. No build, install,
Prisma generation, migration, service operation or user-data read was performed.
The source checkout has no node_modules. Standard AVA preloads src/prelude.ts,
which reads cwd .env and configuration/private-key files. Do not run it against
this live checkout or a real user HOME/config.

In a dependency-complete, isolated source copy with synthetic
HOME/config and no private .env, generate the Prisma client, then run:

    yarn workspace @affine/server test src/core/workspaces/__tests__/main-board-seed.spec.ts src/core/workspaces/__tests__/main-board.spec.ts src/core/workspaces/__tests__/main-board.controller.spec.ts

Before deployment additionally verify real HTTP AuthGuard failures and isolated
multi-connection PostgreSQL uniqueness/rollback/restart behavior, plus native
page/surface acceptance in the actual client. Do not repair a missing native
binary by changing machine configuration as part of this feature.
